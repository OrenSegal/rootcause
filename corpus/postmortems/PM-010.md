---
id: PM-010
title: Fail-fast timeout set too low cascaded into callers
date: '2025-11-12'
services: [inventory, checkout]
---
Inventory lowered its database statement timeout tenfold to fail fast. Normal queries took longer than the new limit, so inventory started canceling its own queries and returning 500s. Checkout, which calls inventory, paged first.

A checkout release in between the change and the page drew attention away from inventory.

Root cause: the timeout value in inventory's config. The service that pages is not always the one at fault: look upstream for the first errors.

Fix: restored the timeout; timeouts now set from measured p99 plus margin.
