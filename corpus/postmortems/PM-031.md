---
id: PM-031
title: Connection leak in a retry wrapper surfaced hours later
date: '2026-02-25'
services: [notifications, postgres]
---
A notifications release added a retry wrapper that did not release its database connection when a send failed. Pool usage grew slowly for hours and the pool ran dry in the evening. A small config release shortly before the outage was blamed first.

How to tell: a pool usage line that climbs steadily since an older release, and warnings about connections held far longer than any request.

Root cause: the older release's code. Fix: fixed the wrapper; alert on connection hold time.
