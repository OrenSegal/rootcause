---
id: PM-001
title: Orders connection pool cut during a config cleanup
date: '2025-03-11'
services: [orders, postgres]
---
A release that tidied up settings for the orders service also changed the database pool ceiling from 40 to 4. Nobody reviewed the value because it sat in a config-only diff next to a logging change.

Impact: 35 minutes of slow and failed order writes. Error rate peaked at 9%.

What we saw: "timeout acquiring connection from pool" errors with in_use equal to the ceiling and a long wait queue, while the database itself had fewer active connections than usual.

Root cause: the pool ceiling, not the database. Fewer connections in use on the database side while the application waits is the signature.

Fix: restored the ceiling, added a lint rule that flags pool sizes changed by more than 50% in one release.
