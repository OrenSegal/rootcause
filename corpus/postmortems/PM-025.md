---
id: PM-025
title: Migration rewrote a large table under an exclusive lock
date: '2025-07-21'
services: [orders, postgres]
---
A release added a NOT NULL column with a default to a 40-million-row table. On our Postgres version that rewrote the table while holding an exclusive lock, and every insert waited until it timed out.

The same release changed a log level, and the config diff showed only that, which sent the investigation the wrong way.

Fix: killed the migration, re-ran it as add nullable column, backfill in batches, then add the constraint. Root cause category: the release's code (the migration), not its config.
