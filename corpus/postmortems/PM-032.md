---
id: PM-032
title: Tighter query budget applied by a config reload
date: '2026-04-22'
services: [search]
---
A search release lowered the per-query timeout from 2000ms to 200ms. The new value took effect only when the next config reload ran a few minutes later, and from then on slower queries were canceled. A payments release in between was the last deploy before the errors.

How to tell: errors name the timeout setting, p99 is pinned at the new limit, and a config reload line precedes them.

Fix: restored the budget; reloads now log the release they come from.
