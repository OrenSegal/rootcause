---
id: PM-026
title: Cache flush stampeded the database
date: '2026-01-13'
services: [redis, postgres, product-api]
---
An operator ran a runbook step that flushed the product cache. Every request missed at once and went to the database, which ran out of connection slots within seconds. The product API returned errors until the cache refilled.

No deploy was involved; a catalog release shortly before was suspected. The flush was in the ops audit log.

Root cause: resource exhaustion on the database, triggered by the flush. Fix: the runbook now warms the cache key by key, and the API limits concurrent misses.
